RabbitMQ 概述

Created2026-06-17|Updated2026-06-18|RabbitMQ
|Post Views:

RabbitMQ 使用 Erlang 语言开发的开源消息队列系统，基于 AMQP 协议实现。

概述

优势

  • 开源、性能优秀，稳定性保障
  • 提供可靠消息投递模式(confirm)、返回模式(return)
  • 与 Spring AMQP 成熟集成
  • 集群模式丰富
  • 保证消息不丢失的前提做到高可靠性、可用性

AMQP 高级消息队列协议

AMQP(Advanced Message Queuing Protocol 高级消息队列协议) 是具有现代特征的二进制协议。提供统一消息服务的应用层标准高级消息队列协议。为面向消息中间件设计的应用程开发标准协议。

AMQP 核心概念

  • Server: 又称 Broker 接受客户端连接，实现 AMQP 实体服务（每个 RabbitMQ 服务器都是一个 Broker ）

  • Connection: 连接，应用程序与 Broker 的网络连接

  • Channel: 网络信道，代表一个消息会话，对消息的读写都是在 Channel 中进行，一个客户端可以有多个 Channel

  • Message: 消息，服务器与应用程序之间传递的数据，由 Properties 和 Body 构成

    • Properties 消息属性（优先级、延迟等高级特性）
    • Body 消息体内容

  • Virtual host: 虚拟主机，用于逻辑隔离最上层的消息
    一个 Virtual Host 可以有若干个 Exchange 和 Queue 并且不能重复；不同的 Virtual Host 可以用来隔离不同的微服务域。

  • Exchange: 交换机，接收消息并根据路由键转发消息到绑定的队列

  • Binding: Exchange(交换机)和Queue(队列)之间的虚拟连接， Binding 中可以包含 routing key

  • Routing key: 用来确定交换机到队列之间的路由规则

  • Queue: 也成为 Message Queue(消息队列)，实际保存消息并将消息转发给消费者

RabbitMQ 核心概念

  1. ConnectionFactory 获取连接工厂(配置Broker IP/Port username/password)
  2. Connection: 通过工厂获取链接
  3. Channel: 通过连接创建数据信道，发送和接收消息
  4. Queue: 具体的消息存储队列
  5. Producer & Consumer: 生产和消费者

消费者支持两种消费模型：push 推送 和 pull拉取 两种方式

交换机(Exchange)

交换机(Exchange): 接受消息，根据路由键转发消息到所绑定的队列。

交换机配置属性

  • Name: 交换机名称
  • Type: 交换机类型
    • direct 直连交换机
    • topic: 主题交换机
    • fanout: 扇出交换机
    • headers: 头交换机
    • sharding(通过插件 rabbitmq_sharding支持):
  • Durability: 是否持久化(true: 持久化)
  • Auto Delete: 自动删除；当最后一个绑定到交换机上的队列删除后，是否自动删除交换机
  • Internal: 当前交换机是否用于 RabbitMQ 内部使用，默认 false
  • Arguments: 扩展参数，用于扩展 AMQP 协议自定义使用

交换机类型

  • direct: 直连交换机(默认名称： #empty string# / amqp.direct)

    所有发送到直连交换机的消息被转发到与 routing key 绑定的队列。如果绑定队列不存在，则丢弃消息。

    通过 channel.queueBind() 将 routing key 与队列绑定。

    直连主交换机模式可以使用 RabbitMQ 自带的交换机: default exchange ，所以不需要将交换机(exchange)进行任何绑定(binding)操作；

    消息传递时， routing key 必须完全匹配才会被队列接收，否则将被丢弃(即，使用默认交换机时的 routing key 与队列名必须是相同的)。

  • topic: 主题交换机(默认名称： amqp.topic)

    所有发送到主题交换机的消息通过通配符匹配进行路由，将消息发送到匹配的队列。

    routing key 与 bingding key 可以模糊匹配时，消息被传递到绑定 binding key 的队列中。

    Topic 交换机 Routing key 通配符：

    • . 分隔不同的词
    • # 匹配一个或多个词
    • * 匹配一个词

  • fanout: 扇出交换机(默认名称： amqp.fanout)

    (不使用 routing key)简单的将队列绑定到交换机。发送到交换机的消息都会被转发到与该交换机绑定的所有队列上。

    扇出交换机转发消息是最快的（不需要做匹配）。

  • headers: 头交换机；根据头部信息进行路由(默认名称：amqp.match/amqp.heardes)

  • sharding: 通过插件 rabbitmq_sharding支持

队列(Queue)

Queue 实际存储消息数据。

队列配置属性

  • Name: 队列的名称
  • Durability: 是否持久化，(Durable 是，Transient 否)
  • Exclusive: 独占，只被一个连接(connection)使用，当连接关闭后队列被删除
  • Auto delete: 是否自定删除；当设置自动删除时，最后一个监听被移除后队列会自动被删除
  • Arguments: 额外的高级控制参数

连接(Connection)

连接通常是长连接，使用认证机制并且提供 TLS (SSL) 保护。

通道(Channel)

通道处理多个连接，实现对连接复用（即，多个通道共享同一个连接）。

绑定(Binding)

Binding 绑定描述交换机与交换机或队列之间的连接关系。

Binding 中可以包含 routing key 或者其它参数。

消息(Message)

服务器与应用程序之间传递的数据。

消息由 Properties 和 Payload(Body) 组成。

消息属性

  • delivery mode: 持久化方式
  • headers: 自定义内容
  • content_type: 编码字符集
  • content_encoding
  • priority: 优先级
  • correlation_id: 消息唯一 id
  • reply_to: 重试队列
  • expiration: 过期时间
  • message_id: 消息id

常用的自定义属性：

  • timestamp: 时间戳
  • type:
  • user_id:
  • app_id:
  • cluster_id:

虚拟主机(Virtual host)

虚拟主机用于进行逻辑隔离，最上层的消息路由。一个虚拟主机中可以有多个交换机和队列。

同一个虚拟主机中不能有同名的交换机与队列。

RabbitMQ 高级特性

生产端消息可靠投递

关注点：

  • 保障消息的成功发出
  • 保障 MQ 节点的成功接收
  • 发送端收到 MQ 节点(Broker)确认应答
  • 完善的消息进行补偿机制

解决方案

消息要首先写入数据库后在进行发送，而不是先发送后入库。

方案一：消息信息落库，对消息状态进行打标

  1. 业务数据与消息信息落库(两次数据库操作)
  2. 消息发送
  3. 生产端的 Confirm Listener 监听接收消息应答 confirm
  4. 更新消息信息库记录为已可靠投递
  5. 分布式定时任务查询消息信息未成功投递的记录
  6. 重试消息发送
  7. 当消息超过重试次数，更新消息为投递失败，由补偿机制处理

缺点：需要读取两次数据库写入操作，在高并发下将造成数据库瓶颈。

方案二：消息延迟投递，做二次确认，回调检查

  1. 业务数据落库
  2. 发送消息
  3. 延迟消息投递检查
  4. 消费者消费消息
  5. 发送 confirm 确认消费
  6. 在 Callback service 中接收到监听的确认消费消息
  7. 检查消息细节，在 Step2 延时到达时确定是否有匹配的 Confirm ，如果没有则通过 RPC 调用 Upstream service 消息重发。

减少写入数据库，保证吞吐。

消费端消息幂等性保障

幂等性概念

对一个操作重复执行时结果不会产生差异。

3. 命令行工具

rabbitmqctl 服务管理
rabbitmq-server 服务管理
rabbitmq-plugins 插件管理

3.1 rabbitmq-server

  • 前台启动服务: rabbitmq-server start

3.2 rabbitmqctl

  • 启动服务: rabbitmqctl start_app

  • 关闭服务: rabbitmqctl stop_app

  • 查看节点状态: rabbitmqctl status

  • 添加密码为 ##password## 的 ##username## 用户: rabbitmqctl add_user _##username##_ _##password##_

  • 查看系统内所有用户: rabbitmqctl list_users

  • 删除 ##username## 的用户: rabbitmqctl delete_user _##username##_

  • 清理 ##username## 用户对虚拟主句 ##vhostpath## 的权限: rabbitmqctl clear_permissions -p _##vhostpath##_ _##username##_

  • 查看用户 ##username## 的权限: rabbitmqctl list_user_permissions _##username##_

  • 修改 ##username## 用户密码为 ##new-password##: rabbitmqctl change_password _##username##_ _##new-password##_

  • 设置权限: rabbitmqctl set_permissions -p _##vhostpath##_ _##username##_

  • 创建虚拟主机: rabbitmqctl add_vhost _##vhostpath##_

  • 查看所有虚拟主机: rabbitmqctl list_vhosts

  • 查看虚拟主机的权限: rabbitmqctl list_permissions -p _##vhostpath##_

  • 删除虚拟主机: rabbitmqctl delete_vhost _##vhostpath##_

  • 查看所有队列: rabbitmqctl list_queues

  • 清空队列中的消息: rabbitmqctl -p _##vhostpath##_ purge_queue _##queue##_

  • 清理所有数据(要在 rabbitmqctl stop_app 之后使用): rabbitmqctl reset

  • 加入集群: rabbitmqctl join_cluster _##clusternode##_ [--ram]

  • 查看集群状态: rabbitmqctl cluster_status

  • 修改集群节点的存储形式: rabbitmqctl change_cluster_node_type disc|ram

  • 摘除节点: rabbitmqctl forget_cluster_node [--offline]

  • 修改节点名称: rabbitmqctl rename_cluster_node oldnode1 newnode1 [ oldnode2 newnode2 ...]

3.3 rabbitmq-plugins

  • 启用管理插件：rabbitmq-plugins enable rabbitmq_management
  • 启用 STOMP 插件: rabbitmq-plugins enable rabbitmq_stomp
  • 启用 STOMP web 插件: rabbitmq-plugins enable rabbitmq_web_stomp
